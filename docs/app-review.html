What's already working

The provider abstraction is clean and correctly concurrent — two probes under asyncio.gather, prefix-based routing, graceful omission of unreachable providers. Wizard state lives in useWizardController, so WizardPage stays presentational. ApiError carries the backend's detail string all the way to the UI. Every fetching useEffect uses an ignore flag against unmount races. Deliverable merge semantics preserve unselected outputs, and a test proves it. react-markdown runs without rehype-raw, so model output cannot inject HTML — keep it that way.

Five findings, in the order worth fixing them

Ranked by damage done today, not by how interesting they are. The first two cost users real work and real GPU minutes — both are now fixed, and are kept here with their resolutions rather than deleted. Finding 04 is half closed: the app no longer listens on a routable interface and no longer ships a credential, but it still has no authentication. Findings 03 and 05 are open.

01
Fixed Was: Critical Correctness UX

A partial generation failure throws away everything that succeeded

Resolution

The gather now uses return_exceptions=True and partitions outcomes: successes merge into the Deliverable, failures become typed DeliverableFailure entries on a new GenerationResult. Total failure still raises, preserving the 400/502 mapping — reporting success when nothing generated would be a lie. The router persists partial output before returning.

On the frontend an ensureProject() helper backed by createdId state means a retry updates the same record instead of forking a new one — handleRefine had the identical bug and shares the helper. Results renders an “n of m generated” banner naming what failed, counted over requested keys so regenerating a subset reports the right ratio.

Verified by test_partial_generation_is_persisted · test_total_generation_failure_returns_502

Originally reported at backend/app/services/deliverables.py:104

generated = await asyncio.gather(*(run_one(key) for key in deliverable_keys))

Without return_exceptions=True, the first exception propagates and cancels the rest. Pick the Agent Handoff preset (three deliverables), have the third time out at 120s, and the two that already completed — several minutes of local GPU time — are discarded. save_deliverables is never reached, the endpoint returns 502.

It compounds on the frontend. handleGenerate creates the project before generating, and on failure editId is still null: 

const projectId = editId ?? (await createProject(projectData)).id

So every retry writes another orphan row. Three failed attempts leave three identical projects in the Library.

Fix

Gather with return_exceptions=True, persist whatever succeeded, and return per-deliverable status so the UI can offer “2 of 3 generated — retry Agent Prompt.” On the client, hold the created id in state (or navigate to ?edit=<id> right after creation) so a retry updates instead of duplicating.

02
Fixed Was: Critical Performance Reliability

Every database call blocks the event loop

Resolution

The five storage-only handlers are now plain def, so FastAPI runs them in its threadpool. generate and refine stay async def — they await the providers — and push their storage calls through run_in_threadpool. The engine gained pool_pre_ping=True, pool_recycle=1800.

Covered by a new tests/test_projects_router.py. Those tests use a file-backed SQLite database via tmp_path, because :memory: is not shared across threads and the threadpool handlers would otherwise hit an empty database.

Originally reported at backend/app/storage.py · backend/app/routers/projects.py

storage.py is entirely synchronous PyMySQL, and every route in projects.py is async def. FastAPI runs async def handlers directly on the event loop — only plain def handlers get the threadpool. So each session.get() stalls the whole server, including in-flight generations and the /api/models probe. Against MariaDB on raspberrypi.local, that stall is a network round trip, measured in tens of milliseconds per query.

The same file opens the engine with no connection health check: 

_engine = create_engine(url, future=True)

MariaDB drops idle connections after wait_timeout. The first request after a quiet period gets a dead pooled connection and a “MySQL server has gone away” 500 — intermittent, and miserable to debug.

Fix

Drop async from the five storage-only handlers so FastAPI runs them in the threadpool; wrap the storage.* calls inside the generation routes in run_in_threadpool. Add pool_pre_ping=True, pool_recycle=1800 — two keyword arguments that remove an entire class of intermittent failure. Longer term, move to aiomysql and AsyncSession.

03
Fixed Was: High Feature UX

Generation is a blind 120-second wait

Resolution

Fixed. Generation now uses a POST SSE stream consumed with fetch. LM Studio SSE and Ollama NDJSON deltas render in Results as they arrive; each completed deliverable is persisted independently; AbortController stops unfinished provider streams and reloads completed saved work. The buffered endpoint remains compatible.

Verified by: test_lmstudio_stream_yields_content_deltas, test_ollama_stream_yields_response_until_done, test_stream_generate_routes_prefix_and_rejects_unknown, test_prepare_generation_validates_before_building_prompts, test_stream_persists_before_completed_and_keeps_partial_failures, test_stream_cancels_unfinished_provider_when_consumer_closes, test_encode_sse_uses_named_json_frame, test_stream_generation_persists_completed_deliverable, test_stream_generation_validates_before_opening_stream, the readGenerationStream split-frame and malformed-data cases, the controller immediate-handoff case, the generation-hook completion/cancellation/failure/unmount cases, and the Results live/cancel/error/saved-mode/history cases.

frontend/src/pages/wizard/useWizardController.ts:212 · backend/app/providers.py

Originally, handleGenerate fired one buffered request and showed only a counting timer. A local 7B model producing three long markdown documents could sit near the 120s httpx timeout with zero feedback or cancellation.

The provider APIs already supported streaming. LM Studio accepts "stream": true on /v1/chat/completions, and Ollama streams when requested. The original buffered implementation did not expose either stream to Results.

Implemented: POST /api/projects/{id}/generate/stream emits named SSE events, including incremental {deliverable, delta} data. Results renders those deltas immediately, and its AbortController cancels unfinished provider streams.

04
Partly fixed High Security

The API is unauthenticated and bound to every interface

Originally reported at backend/app/main.py:37 · docker-compose.yml · backend/app/storage.py:14

Resolution — exposure and credential

The listen address is now HOST/PORT, defaulting to 127.0.0.1:8001. Both Dockerfiles moved to shell form so that default survives containers — the --host 0.0.0.0 in backend/Dockerfile would otherwise have overridden it silently.

The frontend dev server was bound the same way. Under network_mode: host it proxies /api to the backend, so leaving Vite on 0.0.0.0 would have republished the API that had just been pulled back to loopback.

DEFAULT_DATABASE_URL is gone. A missing DATABASE_URL raises at startup with a message naming .env.example, rather than guessing a host and password. Four tests in tests/test_configuration.py hold both defaults in place.

Still open — authentication

Anything that can reach the port still has unrestricted access, and /generate still has no concurrency cap. Loopback is a boundary, not a control: it needs a shared-secret header or a single-user session before the app runs anywhere shared, plus a one-in-flight semaphore on /generate that doubles as backpressure for a single local GPU.

Three things stacked as reviewed:

  • uvicorn.run(app, host="0.0.0.0", port=8001)
  • network_mode: host on both compose services
  • No authentication, authorization, or rate limiting on any endpoint

Anyone on the same network can list, read, edit, and delete the entire project library, and can POST to /generate to occupy the GPU indefinitely. The CORS allowlist constrains browsers, not curl.

Alongside it, a fallback DSN with a credential baked into source:

DEFAULT_DATABASE_URL = "mysql+pymysql://buildbrief:password@raspberrypi.local:3306/buildbrief"

High Maintainability Test coverage

No migrations, no API tests, no frontend tests, no CI

init_db() calls create_all, which creates missing tables and ignores changed ones. The first added or widened column means manual DDL on every deployment. Adopt Alembic now, while there are two tables and no external users.

Coverage was 174 lines against 2,454 lines of application code, all of it below the HTTP layer. Revisions 2 and 3 added tests/test_projects_router.py and tests/test_configuration.py (415 test LOC now), so the routers and the environment handling are covered; the provider clients and every React component still are not.

Fix
  • Routers — TestClient: 404 paths, the GenerateRequest validation boundary, the 502 mapping. Done — six tests covering the CRUD round trip, 404s, 422 on an unknown deliverable key, partial-generation persistence, total-failure 502, and the 400 unknown-prefix path.
  • Providers — httpx.MockTransport: prefix routing, unreachable fallback, and malformed payloads (r.json()["choices"][0] raises KeyError → unhandled 500).

  • CI — one workflow running uv run pytest, npm run lint, tsc -b. All three pass today, so it starts green.
Performance

Wasted round trips and blocked paint

Library search fires a request per keystroke High

frontend/src/pages/LibraryPage.tsx:32

The effect depends on [platform, query], so typing “planner” issues seven requests with no debounce and no abort. Responses can resolve out of order and a stale one wins. Debounce to ~250ms and cancel the previous request with an AbortController.

The same filter runs twice Medium

frontend/src/pages/LibraryPage.tsx:50

listProjects already applies q and platform server-side; filteredProjects re-applies both on the client. Beyond dead work, it's a correctness trap — server-side ilike and client-side toLowerCase().includes() diverge on the first non-ASCII title. Render projects directly.

Unindexed sort column Medium

backend/app/storage.py:176

Every list query orders by updated_at DESC, created_at DESC and neither column is indexed. Add index=True to updated_at. The ilike '%term%' search can't use a B-tree at all — a MariaDB FULLTEXT index on (title, description) is the upgrade path.

Pagination exists in the API but not the UI Medium

limit/offset are implemented and validated; LibraryPage hardcodes limit: 100. Past 100 projects, briefs silently vanish.

Markdown renderer ships in the initial bundle Medium

react-markdown and remark-gfm are only used on /results/:id. React.lazy on ResultsPage moves roughly 100KB off the path to first paint on the wizard — which is the landing route.

Google Fonts import is render-blocking Medium

frontend/src/index.css:1

A CSS @import for three families and twelve weights blocks rendering until it resolves. Move it to preconnect + link rel=stylesheet in index.html, trim to the weights actually used, add font-display: swap.

Concurrent generation may be counterproductive locally Medium

asyncio.gather fires three requests at one local model server. LM Studio and Ollama queue them, so wall-clock time is unchanged at best; with a large model, three concurrent contexts can push VRAM into swap. Worth measuring — a sequential loop with per-deliverable progress may be both faster and better UX.

Security

Input boundaries and deployment posture

No input length limits High

backend/app/schemas.py:10

ProjectCreate accepts unbounded strings for every field. They're concatenated into the prompt and stored in TEXT columns (65,535 bytes — longer raises DataError). A 500KB extra_context blows the model's context window and then fails the insert. Add Field(max_length=…): 200 for title, ~5,000 for the long fields.

Unvalidated platform query parameter Medium

backend/app/routers/projects.py:23

The list endpoint types platform as a bare str while ProjectCreate uses a Literal. An arbitrary value returns an empty list rather than a 422. Reuse the Platform literal.

Provider responses are trusted Medium

backend/app/providers.py:62, :103

r.json()["choices"][0]["message"]["content"] assumes a well-formed payload. A provider returning an error object yields KeyError → an unhandled 500. Parse defensively and map to a 502 with a message that names the provider.

Prompt injection is inherent, and currently contained Note

Project text flows into the prompt, so a user steers their own generation — that's the product working. It only becomes a vulnerability the day BuildBrief gains shared projects or a public gallery, when generated markdown becomes attacker-controlled content in someone else's browser. The react-markdown setup without rehype-raw is what keeps that safe; guard it with a comment and a test.

Compose file is a development configuration Medium

--reload, source bind-mounts, and Vite's dev server. Correct for local work, but the README presents it as the way to run BuildBrief. Add a production target — multi-stage frontend build served as static files, no --reload — before this runs anywhere unattended.

Code quality

Small things that will bite later

DeliverableKey is defined twice

models.py:4 has DeliverableKey = str; schemas.py:5 has the Literal. The first is unused and will silently weaken typing the moment someone imports the wrong one. Delete it.

@app.on_event("startup") is deprecated

main.py:32 — move to the lifespan context manager before FastAPI removes it.

Scratch files are committed

frontend/themes_scratch.css (132 lines) and frontend/gen_themes.py (193 lines) are build-time scratch, not app source. Delete them or move them under tools/ with a note on how they're run — and per this project's conventions, that generator should be invoked with uv run.

Refinement question parsing is fragile

deliverables.py:123 strips leading 0123456789. )- from every non-empty line and takes five. A model that opens with “Here are five questions:” returns that preamble as question one. Ask for JSON, keep the line parser as fallback.

save_deliverables can't clear a field

storage.py:213 skips None — the right merge semantic for generation, but it means no single deliverable can be deleted. Fine today; worth a comment so it isn't mistaken for a bug.

No React error boundary, and pad() lives in four files

Any render-time exception blanks the page; one boundary around <Outlet /> in Layout costs ten lines. And pad() is duplicated across WizardPage, ResultsPage, LibraryPage, and GenerateStep.

UX

Three rough edges in the daily path

The theme flashes on every load

ThemePicker reads localStorage in a useEffect, which runs after first paint — so a Gruvbox Light user sees a dark navy flash on every navigation. Set data-theme from a tiny inline script in index.html, before the bundle loads.

Results are download-only

Export writes a .md file; there's no copy-to-clipboard. For the Agent Prompt deliverable, copy is the primary action — the whole point is pasting it into a coding agent. Add a copy button per section.

formatDate will render “Invalid Date”

ResultsPage seeds project state from location.state with created_at: '', and LibraryPage.formatDate passes strings to new Date() unguarded.

Feature suggestions

Where the next build effort pays off most

Streaming generation Done

Delivered under finding 03. It changed how the app feels more than anything else on this list.

Regenerate a single deliverable

The API already supports it — GenerateRequest.deliverables takes a subset and the merge preserves the rest. Only the wizard exposes it, and only as a full four-step round trip. A “Regenerate this section” button on the Results page, with its own model and preset picker, sits on machinery that already exists.

Deliverable versions

Regenerating overwrites in place, so a worse result destroys a better one. A deliverable_versions table keyed by (project_id, key, created_at) plus a version switcher turns “regenerate” from a gamble into an experiment — and it's what makes comparing local models actually useful.

Editable prompt templates

DELIVERABLE_PROMPTS and PRESET_INSTRUCTIONS are hardcoded dictionaries. Surfacing them as per-project overrides costs one table and one settings view, and it's the difference between a fixed tool and one people tune to their own way of writing specs.

Export as a zip, not a concatenated file

The bundle export joins markdown into a single document. A zip containing specification.md, implementation-plan.md, and AGENTS.md — laid out as a directory you drop into a new project — matches how the output is actually used.
